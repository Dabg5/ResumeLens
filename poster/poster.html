ResumeLens

Does a résumé satisfy the formal pattern of a profile?

Daniel Barragan · Jacobo Rodriguez
Nicolas Mejia
Icesi University · Computación y Estructuras Discretas III · 2026-2

The problem

  • One skill, many spellings: JS, React.js, NodeJS.
  • Scores hide why a candidate matches.
  • ResumeLens checks a pattern. It never ranks people.

Five steps, five formal models

Normalize: transducers (FST)

A Finite-State Transducer (FST) rewrites text. At the end marker $ it prints the canonical name.

Recognize: finite automata

Loops: several skills per category. Dashed ε: optional category skipped.

One résumé, four verdicts

JS · React.js · NodeJS · Postgres · Git
JAVASCRIPTREACTNODE_JSPOSTGRESQLGIT
Full Stack ε-NFAACCEPTED
ML Engineer DFA · 3 missingREJECTED
DevOps ε-NFA · 5 missingREJECTED
Data Engineer DFA · 4 missingREJECTED

Full Stack path: q0→q1→q2→q3→q4 ε→q5→q6

Validated with a DSL (textX)

candidate "Wednesday Addams" {
  classification {
    profile full_stack: ACCEPTED
      sequence [JAVASCRIPT, REACT, …]
  }
}

A Domain-Specific Language (DSL) grammar validates each candidate. Invalid text is rejected.

Take-aways

  • Each step is a testable formal model.
  • One résumé can match several profiles.
