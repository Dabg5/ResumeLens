ResumeLens

Formal-Language-Based Résumé Screening

Does a résumé's set of extracted qualifications satisfy the formal pattern of a professional profile?

Jacobo Rodriguez · Daniel Barragan · Nicolas Mejia   |   CyED3 · Integrative Task 1 · Icesi University · 2026

Problem & contribution

Résumé screening often mixes keyword search with opaque scoring. ResumeLens demonstrates a transparent alternative: represent each profile as an ordered formal-language pattern and show exactly which qualifications satisfy it.

Design principle

The system decides pattern membership only. It does not rank candidates or claim that a formal match measures job performance.

Input

Plain-text résumé content, pasted, uploaded, or selected from seven examples.

Processing pipeline

Résumé text→Regex extraction→FST normalization→Profile sorting→DFA / ε-NFA→DSL validation→HTML / Markdown

Surface spellings map to canonical identifiers; a category's alternatives share a transition. Recognition returns a verdict, state trace, and any missing required category.

Input: JS · React.js · NodeJS · Postgres · Git
Canonical: JAVASCRIPT · REACT · NODE_JS · POSTGRESQL · GIT
Full Stack: q0 → q1 → q2 → q3 → q4 → q6 | ACCEPTED

Four profile patterns

Full Stack Developer
ε-NFA
Frontend · framework · backend · database · optional API · version control
Machine Learning Engineer
DFA
Python · data processing · ML framework · database · version control
DevOps Engineer
ε-NFA
Scripting · containers · orchestration · CI/CD · cloud · optional IaC · version control
Data Engineer
DFA
Python · query · processing · orchestration · warehouse · version control

Formal models

ML and Data Engineering are DFAs: categories are disjoint and each symbol has at most one next state.

Full Stack and DevOps are ε-NFAs: an optional category is skipped using an ε transition.

For category Cᵢ, each qualification advances to the next state; a loop permits multiple qualifications in that category. Choices within a category are alternatives.

Language: C₁⁺ C₂⁺ … Cₙ⁺; an optional category uses Cᵢ*.

Evaluation & examples

Seven sample résumés exercise positive, incomplete, and noisy spelling cases.

  • Wednesday Addams → Full Stack accepted
  • Mary Jane Watson → ML Engineer accepted
  • Bruce Banner → Data Engineer accepted
  • Tony Stark → DevOps accepted
  • Missing Git or noisy spellings → no complete match

Tests check extraction, alias normalization, automaton acceptance, explanations, DSL validity, and all reference samples.

Limits & next steps

  • Regex extraction depends on plain-text spelling and layout.
  • Education entries are paired with institutions by appearance order.
  • Category patterns encode team definitions, not universal hiring criteria.
  • Extend extraction to structured CVs and evaluate patterns with domain experts.
